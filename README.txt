- **Model**: For the state of the model, I decided to use a context of 40 on my last run. Here each prediction saw 81 frames by looking at the target plus the 40 on each side. One 32-bin frame is generally ambiguous on its own because neighboring sounds bleed into each other. Since the writeup recommended between 0-50, I decided not going any further based on my time constraint and just previously doing 30 without much of an increase in accuracy scores. 
Apart from that, I did 1536 * 7 then 1024 with 8 hidden layers, which was in the writeup range of 2-8. From an earlier lecture, we learned that depth generally beats width. Each layers smooths the function from the previous one. 
For the usage of BatchNorm, it seemed to converge much faster than my first run. It handles that covariate shift, and is why it generally converges faster and reaches a much better result after that second run.
I decided to use GeLU instead of ReLU because I like its more probabilistic decision based output, and it was converging faster in a test of both in the first four epochs. However, researching more, it appears that ReLU does better with BatchNorm (or is at least more used), so that may have been slightly a design mistake from me, but within time-constraints wasn't worth changing for a full training run.
For dropout rate, I used 0.10. Since dropout and batchnorm tend to work against one another, I wanted to set it lower. Also, my earlier runs seemed to be still underfitting. 
Finally, I had a total of about 19.77 million parameters which is under that 20 million cap that was mentioned in the writeup. I still wanted to use as much as I could within reason. 
- **Training Strategy**: First, I used AdamW at 2e-3. Adam combines momentum with RMSprop, tracking that first and second moments of the gradient as we discussed in a prior lecture. 
I also used weight decay of 0.01. This is the L2 penalty, which the lecture showcased that we have the same idea as multiplying the weights by (1-beta) each step. Small weights generally mean a smoother decision boundary and activation slope.
Also, warmup was started at 1% of 2e-3, so that the first steps stay small while the BatchNorm statistics and Adam's moment estimates are still settling.
The cross-entropy with label smoothing was 0.1. From the lecture, we learned that cross-entropy was used such that KL divergence is convex as a function of the logits. Smoothing targets 0.9 instead of 1.0 would work against noisy frame labels at phoneme boundaries where the true label would be generally uncertain. 
Next, a batch of 2048 was used. Mini-batch gradient variance falls as 1/B, so larger batches give stable updates and keep the GPU busier. 
Finally, working with the best checkpoint having early stopping to pick the model by held out accuracy rather than just trusting the last step. 
- **Augmentations**: For the usage of augmentations, the lectures generally described it as perturbing the input. To keep the label and the model is then generally forced to treat the nearby inputs alike. Here, the masks are drawn per sample. The center frame is restored because that is the frame that is being labeled. 
Then, computed per-utterance, relates to the cepstral normalization the writeup suggests, and the input-normalization step from our lectures. This removes each speaker's and each recording channel's offset and scale, so the model sees relative spectral shape rather than absolute loudness. 
- **Notebook Execution**: Here the number of workers stayed at 0, since I was using my Windows computer.
